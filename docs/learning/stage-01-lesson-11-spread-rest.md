# Этап 1. Урок 11 — деструктуризация, rest и spread

## Что ты должен понять

Деструктуризация достаёт значения из объекта или массива. Rest собирает оставшиеся значения. Spread раскрывает объект или массив в новую структуру. Символы одинаковые — `...`, но действие определяется местом использования.

## 1. Деструктуризация объекта

```js
const max = {
  name: "Max",
  balance: 5751,
  type: "roblox",
  price: 500,
  quantity: 10,
};

const { name, balance, type } = max;
```

Теперь `name`, `balance`, `type` — отдельные переменные. Имена должны совпадать со свойствами. Переименование:

```js
const { name: buyerName, balance: buyerBalance } = max;
```

Значение по умолчанию применяется, только если свойство равно `undefined`:

```js
const { status = "USER" } = max;
```

## 2. Деструктуризация массива

```js
const [firstBuyer, secondBuyer, ...otherBuyers] = buyers;
```

Позиция важна: первый элемент идёт в `firstBuyer`, второй — в `secondBuyer`. `otherBuyers` — новый массив остатка.

Для массива стандартна запись `[]`. Запись `{ 0: firstBuyer }` технически возможна, но хуже показывает намерение.

## 3. Rest

Rest собирает остаток:

```js
const { name, ...buyerData } = max;
```

`buyerData` получит все свойства, кроме `name`. Исходный объект не изменится.

## 4. Spread объекта

```js
const vipMax = {
  ...max,
  balance: max.balance + 1000,
  status: "VIP",
};
```

Сначала копируются свойства `max`, потом совпадающий `balance` заменяется. Порядок критичен:

```js
const wrong = {
  balance: max.balance + 1000,
  ...max,
};
```

Здесь старый `max.balance` перезапишет бонус.

Spread создаёт новый верхний объект, но не глубокую копию вложенных объектов. Если есть `profile: { level: 1 }`, то копии всё ещё ссылаются на один вложенный `profile`. Для обновления вложенности копируй каждый изменяемый уровень.

## 5. Spread массива

```js
const extendedBuyers = [
  ...buyers,
  { name: "Anna", balance: 5500 },
];
```

Исходный массив не меняется. В отличие от `push()`, создаётся новый массив.

## 6. map + spread

```js
const updatedBuyers = buyers.map((buyer) => {
  if (buyer.name === "Saveliy") {
    return {
      ...buyer,
      balance: 4000,
      status: "VERIFIED",
    };
  }

  return buyer;
});
```

`map()` обязан вернуть элемент для каждого прохода. Для Saveliy возвращается новая копия, для остальных — прежний объект. Новый массив отличается от исходного. Это не полная глубокая копия каждого элемента: неизменённые элементы остаются теми же ссылками, что нормально для точечного immutable-обновления.

## 7. map против forEach

`forEach()` предназначен для действий и возвращает `undefined`. Если внутри менять `buyer.balance`, исходный объект мутирует. `map()` нужен, когда результат — новый массив.

## Типичные ошибки

- `{ name } = buyers` — попытка взять `name` у массива, а не у объекта.
- Дважды объявить `const name` в одном scope.
- Забыть `return buyer` в ветке `map()`.
- Поставить `...buyer` после новых свойств и потерять обновления.
- Считать spread глубокой копией.

## Пошаговая практика

1. Достань первого и второго покупателей через `[]`.
2. Достань `name` первого с переименованием `firstBuyerName`.
3. Создай `vipMax` с бонусом 1000.
4. Сравни `max === vipMax` — ожидается `false`.
5. Через `map()` обнови только Saveliy.
6. Выведи старый и новый объект Saveliy.

## Самостоятельное задание

На своём массиве `buyer` создай новый массив `buyersAfterVerification`:

- Max получает `status: "VIP"`, но баланс не меняется;
- Saveliy получает `status: "VERIFIED"` и бонус 500;
- Ara получает значение по умолчанию `status: "USER"`;
- исходный массив нельзя менять;
- через `every()` докажи, что в новом массиве у всех есть непустой статус;
- через сравнение и вывод докажи, что исходный Saveliy остался прежним.

## Урок закрыт, если

Ты можешь без подсказки объяснить разницу между destructuring, rest и spread, правильно обновить объект через `map()` и не мутировать исходные данные.
