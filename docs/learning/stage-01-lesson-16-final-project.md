# Этап 1. Урок 16 — финальная контрольная ONIX Mini

## Цель

Собрать маленькую самостоятельную систему сделок из всего фундамента JavaScript. Это не production ONIX и не база данных: задача — доказать понимание языка и бизнес-порядка операций.

## Данные

Создай минимум 4 покупателей и 4 товара. У каждого должны быть уникальные `id`. Заказ должен ссылаться на `buyerId` и `productId`, а не дублировать всё имя объекта.

Пример структуры:

```js
const buyers = [
  { id: "u1", name: "Max", balance: 10001 },
];

const products = [
  { id: "p1", name: "Roblox", price: 500, stock: 10 },
];
```

## Обязательные функции

- `validatePrice(price)` — выбрасывает ошибку при плохой цене.
- `validateQuantity(quantity)` — выбрасывает ошибку при плохом количестве.
- `findBuyerById(buyers, id)` — возвращает объект или `undefined`.
- `findProductById(products, id)` — возвращает объект или `undefined`.
- `calculateFinalPrice(price, quantity)` — применяет выбранное правило скидки/комиссии.
- `buy({ buyer, product, quantity })` — возвращает предсказуемый результат, не меняет данные до успешных проверок.
- `buildReport(orders)` — использует `filter`, `map`, `some`, `every`, `reduce`.

## Порядок операции

```text
проверить покупателя
→ проверить товар
→ проверить цену и количество
→ рассчитать итог
→ проверить баланс и stock
→ только теперь изменить баланс и stock
→ вернуть результат
```

## Результат покупки

Используй единый формат, например:

```js
{
  ok: true,
  reason: null,
  buyerId: "u1",
  productId: "p1",
  finalPrice: 4250,
  balance: 5751,
  stock: 5,
}
```

Для отказа `ok` false, баланс и stock должны остаться прежними, а `reason` должен объяснять причину.

## Обязательные сценарии

1. Успешная покупка без скидки.
2. Успешная покупка со скидкой.
3. Нехватка баланса.
4. Нехватка stock.
5. Неизвестный buyer id.
6. Неизвестный product id.
7. Цена 0 и отрицательная цена.
8. `NaN` и `Infinity`.
9. Количество 0, отрицательное и дробное.
10. Покупка на точный баланс.
11. Проверка, что отказ не изменил данные.
12. Отчёт по успешным заказам.

## Ограничения

Не используй React, NestJS, Prisma, базу данных и Cursor для написания решения. Можно использовать документацию для синтаксиса после самостоятельной попытки. Не копируй готовую архитектуру ONIX.

## Критерии приёмки этапа 1

Этап закрыт, если:

- код запускается;
- нет `SyntaxError`, `ReferenceError`, `TypeError`;
- нет неявного `undefined` из бизнес-функций;
- плохой ввод отклоняется;
- отказ не меняет деньги и остатки;
- итог считается один раз и используется в проверке;
- `find/filter/map/some/every/reduce` применены по смыслу;
- исходные объекты не мутируют там, где требуется копия;
- функции разделены по ответственности;
- ты можешь объяснить код без построчного чтения подсказки.

Только после этого ты сам пишешь: «Этап 1 закрыт, готов к этапу 2». До этой фразы переходим только к исправлению и повторению этапа 1.
